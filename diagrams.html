Entropy Machine

Joe Armstrong's vision • Our implementation • The gap

1. Armstrong's Vision: System-Wide Entropy Reduction

The entropy machine operates ACROSS the entire system stack — languages, protocols, representations
Entropic: duplicated ideas
The machine: scans & collapses
Reduced entropy: canonical form
Armstrong: "I know what I would do — I'd write an entropy calculation machine which would look at code and say 'ooh that's the same as that, you could just use that.' And you'd walk the entropy machine up and down, and when you'd finished you'd have a codebase with lower entropy."

2.5. Armstrong's Mechanism: Compression as a Universal Similarity Detector

The core algorithm: Normalized Compression Distance — language-agnostic, format-agnostic
Property Compression-Based (NCD) AST Fingerprinting (ours)
How it works C(A+B) − min(C(A),C(B)) reveals shared structure Walk tree, replace identifiers with $N, hash the structure
Language knowledge None — works on any bytes Requires a JS/TS parser (oxc)
Cross-language Can compare Go function with Erlang function Only compares within same parsed language
Format agnostic JSON vs Erlang term vs SQL row — all bytes Only AST nodes that survive parsing
Granularity Black box: knows they're similar, not why White box: can point to exact AST nodes
Normalization Compression inherently normalizes some redundancy Explicitly normalizes identifiers and literals
Speed O(n²) pairwise compression — expensive at scale O(n) per file — fingerprint + hash map lookup
Fuzzy matching Built-in: similar but not identical things compress together well Only exact structural matches after normalization
Armstrong: "You could compress your codebase. Then you could take one thing at a time and ask: if I remove this, does the compressed size go down significantly? If it does, this thing contained a lot of unique information — it wasn't shared. That's entropy. The things that compress well together are the things that share structure, and those are the duplicates you want to collapse."

4. The Real Gap: Semantic Matching Across Representations

Armstrong's key insight: collapse the same IDEA, not the same CODE
Same concept, different encodings
Collapsed to canonical form
Armstrong: "If you have an identifier for a concept in a system, there should only be one thing that identifies that concept — not five implementations of the same idea scattered through different languages, different protocols, different parts of the stack. The entropy machine finds those and says: this is one thing, treat it as one thing."
